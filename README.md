# 保守ナレッジ閲覧サイト ― GitHub Pages 配置手順

設備故障・対応履歴のデータベースを、タブレットのブラウザから閲覧・検索できる
静的サイト一式です。サーバー不要で、GitHub Pages にそのまま置けます。

## このフォルダの中身（すべて必要）

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み（HTML）。`styles.css` と `app.js` を読み込みます。 |
| `styles.css` | 見た目（レイアウト・配色・スマホ対応のスタイル）。 |
| `app.js` | 動作（DB読込・検索・絞り込み・詳細表示などの処理）。 |
| `recommender.js` | 「類似事例に相談」機能。入力文から近い過去事例を提示（下記）。 |
| `incident_db.sqlite` | データベース本体。**更新したいときはこのファイルを差し替えるだけ。** |
| `sql-wasm.js` / `sql-wasm.wasm` | ブラウザ内でSQLiteを動かすエンジン（同梱済み。CDN不要・オフライン可）。 |
| `sql-wasm-base64.js` / `incident_db_base64.js` | **オフライン用**（`index.html` をダブルクリックで開いたとき用）。自動生成ファイルなので直接編集しないでください。 |
| `make_offline_data.py` | 上記オフライン用ファイルを作り直すスクリプト（DBを差し替えたときに実行）。 |
| `.nojekyll` | GitHub Pages が `.wasm` 等をそのまま配信するためのマーカー（中身は空でOK）。 |
| `serve.py` / `.vscode/` | ローカル開発用の簡易サーバーと VS Code 設定（下記「VS Code での開発」）。 |

フォルダ内のファイルをすべて同じ階層に置いたまま使ってください（相対パスで参照し合っています）。

**毎回DBファイルを選ぶ必要はありません。** 次のどちらの開き方でも自動で読み込まれます。

| 開き方 | 読み込み経路 |
|---|---|
| GitHub Pages・Live Server・`serve.py` など **サーバー経由（http/https）** | `incident_db.sqlite` を直接読み込み |
| `index.html` を **ダブルクリックで直接開く（file://）** | 同梱の `incident_db_base64.js` から読み込み |

（`file://` ではブラウザの制限でファイルを直接読み込めないため、同じデータを
JavaScriptに埋め込んだ `*_base64.js` を使う仕組みにしています。）

### 類似事例に相談（チャット）
画面右上の「類似事例に相談」から、気になる不具合を普段の言葉で入力すると、
語句が近い過去のインシデントをスコア順にお勧めします（カードをタップで詳細表示）。

- 仕組みは、日本語の文字bigram＋BM25（検索ランキング）＋日常語→専門語の同義語展開で、
  **すべてブラウザ内で完結**します。サーバーや外部APIは不要で、オフラインでも動きます。
- 生成AI（LLM）ではなく「似た事例を探して勧める」推薦機能です。文章の生成や要約はしません。
- 言い回しの対応表は `recommender.js` 冒頭の `RECO_SYN`（同義語辞書）で管理しており、
  現場でよく使う言葉を追記すると、より当たりやすくできます。


- `index.html` / `styles.css` / `app.js` の各ソースには、役割・セクション・要点を
  日本語コメントで記載しています（改修時の目印）。色や余白は `styles.css` 冒頭の
  `:root` 変数で一元管理しているので、ここを直せば全体の見た目を変えられます。
- データベースの再現・移行用に、別途 `incident_db_dump.sql`（SQLite復元用）と
  `schema_postgresql.sql`（サーバー型DB移行用）を用意しています（いずれもコメント付き）。
  これらは配信サイトには不要なので、この site フォルダには含めていません。

## VS Code でのローカル開発

このフォルダを VS Code で開けばそのまま編集できます。動作確認の方法は3通りです。

**A. index.html をダブルクリックして開く（一番手軽）**
サーバーなしでそのまま動きます（同梱のオフライン用データを使用）。
ただし `incident_db.sqlite` を差し替えた場合は `python3 make_offline_data.py` を
実行しないと、この開き方のときだけ古いデータが表示されます。

**B. Live Server 拡張を使う（開発中はおすすめ）**
1. VS Code の拡張機能で「Live Server」をインストール。
2. このフォルダを VS Code で開く。
3. `index.html` を右クリック →「Open with Live Server」。
   → `http://localhost:5500` で開き、`incident_db.sqlite` を直接読み込みます。
   （ポートは同梱の `.vscode/settings.json` で 5500 に設定済み）

**C. 同梱の serve.py を使う（拡張機能なし）**
1. このフォルダで `python3 serve.py` を実行。
2. 表示された `http://localhost:5500/` をブラウザで開く。
   （ポートを変える場合: `python3 serve.py 8080`）

B・C はDBファイルを直接読むので、差し替えた内容がすぐ反映されます。
コードを直したら、ブラウザを再読み込みするだけで反映されます（キャッシュ無効化済み）。

---

1. GitHub にログインし、新しいリポジトリを作成（例: `incident-db`）。
2. 作成したリポジトリの「Add file ▸ Upload files」で、**このフォルダ内の全ファイル**
   （`index.html`, `incident_db.sqlite`, `sql-wasm.js`, `sql-wasm.wasm`, `.nojekyll`）を
   アップロードして Commit。
3. リポジトリの「Settings ▸ Pages」を開く。
4. 「Build and deployment」の Source を **Deploy from a branch** にし、
   Branch を **main / (root)** にして Save。
5. 1分ほど待つと、ページのURL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）が表示されます。
6. そのURLをタブレットやスマートフォンのブラウザで開けば、検索画面が出てDBが自動で読み込まれます。
   スマホでは右上のハンバーガーメニュー（≡）から検索・絞り込みパネルが開きます。
   ホーム画面に追加しておくとアプリのように使えます。

### データを更新するとき
1. 新しい `incident_db.sqlite` でファイルを差し替える。
2. **`python3 make_offline_data.py` を実行**して `incident_db_base64.js` を作り直す。
   （ダブルクリックで開いたときに古いデータが表示されるのを防ぐため。サーバー経由でしか
   使わない場合は省略可ですが、実行しておくのが安全です）
3. 両方のファイルをリポジトリにアップロードして上書きCommit。

ページを再読み込みすれば最新データが表示されます（画面側の変更は不要）。

## 動作の前提とよくある点

- **どの開き方でも自動で読み込まれます。** GitHub Pages・Live Server・`serve.py` などの
  サーバー経由では `incident_db.sqlite` を直接、`index.html` をダブルクリックで開いた
  場合（`file://`）は同梱の `incident_db_base64.js` から読み込みます。
- 万一読み込めなかった場合は、画面の「手動でファイルを選択」から `incident_db.sqlite`
  を選べば動きます（フォールバックを用意済み）。
- DBを差し替えたら `python3 make_offline_data.py` を実行してください。実行しないと
  ダブルクリックで開いたときだけ古いデータが表示されます。
- すべての処理はタブレット／PCのブラウザ内で完結し、データは外部に送信されません。

## ⚠ 公開範囲についての注意（重要）

GitHub Pages を**無料の公開（public）リポジトリ**で使うと、ページだけでなく
`incident_db.sqlite` も **URLを知っていれば誰でもダウンロードできる状態** になります。
設備の故障・対応履歴が社外秘に当たる場合は、公開リポジトリでの配信は避けてください。

社内限定で使いたい場合の選択肢:
- **GitHub Enterprise / 組織の限定公開 Pages**（アクセス制御つき）
- **社内Webサーバー＋VPN**（前回ご説明した構成。同じ一式をそのまま置けます）
- ひとまず**ローカルやLAN内だけ**で使う（`python -m http.server` で配信）

中身を確認したうえで、公開してよいデータか必ず判断してください。
